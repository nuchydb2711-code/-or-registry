# OR Registry — ระบบทะเบียนผู้ป่วยห้องผ่าตัด

เว็บแอปทะเบียนและเก็บยอดผ่าตัด ใช้ HTML/CSS/JavaScript + Supabase (PostgreSQL + Auth) ไม่ใช้ Google Sheets เป็นฐานข้อมูล
โครงสร้างข้อมูลและสรุปยอดออกแบบตามไฟล์ทะเบียนเดิมของห้องผ่าตัด (ชีต Data, สรุปยอดผ่าตัดประจำเดือน, Code operation)

> **สถานะ:** พัฒนาครบทุก Phase และทดสอบกับฐานข้อมูลจริงในเครื่องแล้ว แต่ **ยังไม่ได้ทดสอบบน Supabase Cloud ของคุณ**
> ใช้ข้อมูลสมมติเท่านั้นจนกว่าโรงพยาบาลจะอนุมัติให้ใช้ข้อมูลจริง

### ช่องข้อมูลของ Case (ตามไฟล์ทะเบียนเดิม)
วันที่ผ่าตัด · รับจาก ER · คนไข้ถึง OR · Start · Finish · ออกจาก OR/Recovery room · ห้อง OR · HN · ชื่อ-สกุล · อายุ (คำนวณจากวันเกิด ณ วันผ่าตัด) · Diagnosis · Fracture · Operation · ICD-9 · Site · ความเร่งด่วน (Elective/Emergency) · ศัลยแพทย์ · แผนก · การระงับความรู้สึก (GA, TIVA, IVS, SB, BB, LA, MAC ฯลฯ) · ทีมพยาบาล · Ward · Code operation · Class แผล · Major/Minor · ในเวลา/นอกเวลา · ความเสี่ยงและรายละเอียด · ตรวจเวชภัณฑ์ · ODS/MIS

### หลักการนับยอด
- นับเป็น **Case** ไม่ใช่จำนวนผู้ป่วย (รายงานแยก "จำนวนผู้ป่วย (คน)" ไว้ต่างหาก)
- สรุปยอดนับเฉพาะ Case **เสร็จสิ้น** · เลื่อน / ยกเลิก / กำลังดำเนินการ แสดงแยกและไม่นับ
- GA = GA+TIVA+IVS · RA = BB+SB · LA = LA+MAC (ตั้งกลุ่มของแต่ละชนิดได้ที่ ตั้งค่า)

## ติดตั้งทีละขั้นตอน

### 1) สร้างโปรเจกต์ Supabase
supabase.com → **New project** → ตั้ง Database Password เก็บไว้ → Region **Singapore** → รอสร้างเสร็จ

### 2) รัน SQL (SQL Editor → New query → วาง → Run) ตามลำดับ
1. `database/schema.sql`
2. `database/seed.sql` (แผนก ห้อง 1–7 ชนิดยาระงับความรู้สึก)
3. `database/seed_operation_codes.sql` (Code operation 364 รายการจากทะเบียนเดิม)
4. `database/seed_test.sql` (ข้อมูลสมมติ ข้ามได้)

> ถ้าเคยรัน `schema.sql` เวอร์ชัน Phase 1 ไปแล้ว: รัน `migration_phase2.sql` แทนข้อ 1 แล้วรัน `seed.sql` และ `seed_operation_codes.sql` ใหม่

### 3) สร้างผู้ดูแลระบบคนแรก
**Authentication → Users → Add user → Create new user** (ติ๊ก Auto Confirm User) แล้วรัน:
```sql
update public.profiles
   set role = 'ADMIN', is_active = true, full_name = 'ชื่อ-นามสกุล'
 where email = 'admin@example.com';
```
ผู้ใช้คนอื่น: สร้างที่ Authentication → Users เหมือนกัน จะได้สิทธิ์ VIEWER แต่ยังไม่เปิดใช้งาน แล้ว ADMIN ไปกำหนดสิทธิ์และเปิดใช้งานที่หน้า **ตั้งค่า → ผู้ใช้งาน**
(หน้าเว็บสร้างบัญชีให้ไม่ได้ เพราะต้องใช้ service role key ซึ่งห้ามอยู่ฝั่งเว็บ)

### 4) ตั้งค่าเว็บ
เปิด `js/config.js` ใส่ 2 ค่าจาก **Project Settings → API**:
- `SUPABASE_URL` = Project URL
- `SUPABASE_ANON_KEY` = anon public key  (**ห้ามใส่ service_role key** ระบบจะปฏิเสธการทำงานถ้าพบ)

### 5) ขึ้นเว็บ
GitHub Pages: สร้าง repository → อัปโหลดทุกไฟล์ในโฟลเดอร์นี้ (ยกเว้นโฟลเดอร์ `database/` ถ้าไม่ต้องการเปิดเผย) → Settings → Pages → Deploy from branch → เปิดลิงก์ `https://<ชื่อ>.github.io/<repo>/login.html`
หรือเปิดไฟล์ผ่าน Static Hosting ใดก็ได้ที่เป็น HTTPS

ใน Supabase ไปที่ **Authentication → URL Configuration** ใส่ URL เว็บของคุณเป็น Site URL

### 6) ตรวจสอบ
```sql
select tablename, rowsecurity from pg_tables where schemaname = 'public' order by 1;  -- rowsecurity ต้องเป็น true ทุกแถว
```

### 7) ก่อนใช้ข้อมูลจริง
รัน `database/cleanup_test.sql` เพื่อลบข้อมูลสมมติ · ปิดการสมัครเอง (Authentication → Sign In / Providers → ปิด Allow new users to sign up) · เปิด MFA ให้บัญชี Supabase และ ADMIN

## คู่มือใช้งานย่อ (เจ้าหน้าที่)
1. **ลงทะเบียน Case:** เมนู "ลงทะเบียน Case" → พิมพ์ HN กด "ค้นหา HN"
   - พบ: เห็นชื่อ วันเกิด อายุ จำนวนครั้งที่เคยผ่าตัด → กด "เพิ่ม Case ใหม่" (หรือ "ดูประวัติการผ่าตัด")
   - ไม่พบ: กรอกชื่อ วันเกิด เพศ ระบบคำนวณอายุให้ (ไม่สร้างผู้ป่วยซ้ำ เพราะ HN ห้ามซ้ำ)
2. **ขั้นตอน 2:** วันที่ ประเภท Major/Minor/LA แผนก Code operation (เลือกแล้วชื่อ Operation เติมให้) Diagnosis ศัลยแพทย์
3. **ขั้นตอน 3:** ห้อง ยาระงับความรู้สึก เวลาแต่ละช่วง (พิมพ์ชั่วโมง:นาที) สถานะ แล้วกด **บันทึกข้อมูล** หรือ **บันทึกและลงทะเบียน Case ใหม่**
4. ถ้าผู้ป่วยมี Case วันเดียวกันอยู่แล้ว ระบบแจ้งเตือนให้ตรวจสอบก่อนบันทึก
5. **แก้ไข:** เมนู "ทะเบียน" → คลิกแถว → "แก้ไข" · **ยกเลิก Case** ทำได้เฉพาะ ADMIN และต้องระบุเหตุผล (ไม่มีการลบข้อมูลถาวร)
6. **รายงาน:** เลือกช่วงวันที่/ตัวกรอง → "แสดงรายงาน" → Export Excel หรือ PDF
   (PDF: ระบบเปิดหน้ารายงานแล้วเรียกหน้าต่างพิมพ์ ให้เลือก "บันทึกเป็น PDF"; Excel รายตัวที่มี HN/ชื่อ ต้องติ๊กเลือกเอง เฉพาะ ADMIN/STAFF)

## นำเข้าข้อมูลเดิมจาก Excel
ใช้ได้เมื่อโรงพยาบาลอนุมัติให้ใช้ข้อมูลจริงแล้วเท่านั้น (ไฟล์ SQL ที่ได้มี HN และชื่อผู้ป่วยจริง ห้ามอัปโหลดขึ้น GitHub ใช้เสร็จให้ลบทิ้ง)
1. ติดตั้งระบบและรัน `seed.sql` + `seed_operation_codes.sql` ก่อน (ไม่ต้องรัน `seed_test.sql`)
2. รันในเครื่องของคุณ: `pip install openpyxl` แล้ว
   `python3 tools/xlsx_to_sql.py ทะเบียนเดือน.xlsx import.sql`
3. อ่านรายงานที่สคริปต์พิมพ์ออกมา (แถวที่ข้าม, ค่าที่แปลงไม่ได้) ตรวจแก้ใน Excel แล้วรันใหม่ได้
4. เปิด `import.sql` วางใน Supabase SQL Editor → Run (รันซ้ำได้ ไม่สร้างข้อมูลซ้ำ)
5. เปิดรายงาน "สรุปยอดประจำเดือน" เทียบกับชีตสรุปเดิม

ข้อควรรู้: ทุก Case ที่นำเข้ามีสถานะ "เสร็จสิ้น" · ผู้ป่วยที่มีแต่อายุ (ไม่มีวันเกิด) จะได้วันเกิดโดยประมาณ (วันที่ 1 ของเดือน) · Anesth ที่ระบุหลายแบบ เช่น "LA, GA" เก็บเป็น OTHER และใส่ไว้ในหมายเหตุ · ผู้ใช้ผู้สร้าง Case (created_by) ของข้อมูลที่นำเข้าจะว่าง แต่มีบันทึกใน Audit Log

## ความปลอดภัย (สิ่งที่ทำแล้ว)
RLS ทุกตาราง · ตรวจสิทธิ์ที่ฐานข้อมูล (ไม่ใช่แค่ซ่อนปุ่ม) · anon เข้าถึงข้อมูลไม่ได้ · ไม่มีสิทธิ์ลบ Case/ผู้ป่วยจากเว็บ · Audit Log ทุกการเปลี่ยนแปลง (แก้/ลบไม่ได้) · ป้องกันแก้ไขทับกัน · เก็บ session ใน sessionStorage (ปิดแท็บ = ออกจากระบบ) · ไม่เก็บข้อมูลผู้ป่วยใน localStorage · ไม่ใส่ข้อมูลผู้ป่วยใน URL (ใช้รหัสภายใน) · ป้องกัน XSS ด้วยการ escape ข้อความทุกจุด + CSP · ไลบรารีทั้งหมดอยู่ใน `js/vendor/` ไม่โหลดจาก CDN

## ข้อจำกัดและข้อควรระวัง
1. **PDPA:** ข้อมูลผู้ป่วยเป็นข้อมูลอ่อนไหว ต้องได้รับอนุมัติจากโรงพยาบาล (DPO/ฝ่ายสารสนเทศ) ก่อนเก็บบนคลาวด์ต่างประเทศ
2. **สำรองข้อมูล:** แผนฟรีของ Supabase ไม่มี backup อัตโนมัติและโปรเจกต์ที่ไม่ใช้งานจะถูกพัก ใช้งานจริงควรใช้แผนที่มี Daily Backup และสำรองเองเพิ่ม เช่น
   `pg_dump "postgresql://postgres:<รหัสผ่าน>@db.<project>.supabase.co:5432/postgres" -Fc -f or_backup_$(date +%F).dump` เก็บไว้ในที่ของโรงพยาบาล
3. **GitHub Pages เป็น Public:** โค้ดเว็บเปิดสาธารณะ ข้อมูลผู้ป่วยอยู่ใน Supabase และต้อง login ก่อนจึงอ่านได้ อย่าใส่ข้อมูลผู้ป่วยใน repository
4. หน้าเว็บบน GitHub Pages ตั้ง HTTP security header เองไม่ได้ (ใช้ CSP แบบ meta + กันฝังเฟรมด้วย JavaScript) หากต้องการระดับสูงขึ้นให้โฮสต์ที่ที่ตั้ง header ได้
5. PDF สร้างผ่านหน้าต่างพิมพ์ของเบราว์เซอร์ (เพื่อให้ภาษาไทยแสดงถูกต้อง) ต้องอนุญาต pop-up
6. เครื่องมือนำเข้าจาก Excel เป็นสคริปต์ที่รันในเครื่อง (ดูหัวข้อ "นำเข้าข้อมูลเดิมจาก Excel") ไม่มีปุ่มนำเข้าในหน้าเว็บ

## การทดสอบที่ทำแล้ว
- **ฐานข้อมูล:** PostgreSQL 16 จริง ผ่าน 36/36 ข้อ (`database/tests/phase1_test.sql`) ทั้งติดตั้งใหม่และอัปเกรดจากเวอร์ชันเก่าด้วย migration
- **ทั้งระบบ:** รันหน้าเว็บจริงกับ PostgREST + PostgreSQL (เบราว์เซอร์ Chromium) ทดสอบ Login ผิด/ถูก, ลงทะเบียนผู้ป่วยใหม่และ Case, เตือน Case ซ้ำวันเดียวกัน, แก้ไข, ยกเลิกต้องมีเหตุผล, สิทธิ์ ADMIN/STAFF/VIEWER, รายงานทุกแบบ, Export Excel/PDF, หน้าตั้งค่า, Audit Log — ไม่พบ error
- **นำเข้า Excel:** สคริปต์นำเข้าอ่านไฟล์ตัวอย่างได้ 143 Case / 142 ผู้ป่วย รันซ้ำไม่เกิดข้อมูลซ้ำ ยอดหลังนำเข้าตรงกับชีตสรุปเดิม
- **เทียบกับไฟล์ทะเบียนเดิม:** นำข้อมูล 143 รายการของเดือน พ.ย. 2569 เข้าฐานข้อมูลทดสอบ แล้วเปรียบเทียบรายงาน "สรุปยอดประจำเดือน" กับชีตสรุปเดิม ตรงกันทุกตัวเลข (Elective GA/RA/LA = 16/5/88, Emergency = 11/11/8, ER = 6, Closed Fx = 7, Open Fx Gr.1 = 2, ในเวลา/นอกเวลา = 41/100, Class แผล = 25/110/5/1, ยอดตาม Code operation ทั้ง 141 รายการ)
  - ผลต่างที่ตั้งใจ: ระบบแสดง 2 รายการที่ไม่มีข้อมูลในชีตเดิมเป็น "ไม่ระบุ" (รวม 143) และคำนวณ "Total case Fx." เป็น 9 (ชีตเดิมแสดง 0)
